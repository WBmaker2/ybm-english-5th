# 멀티 레슨 골든 벨 앱 디자인

## 목표

기존 Lesson 2 전용 골든 벨 웹앱을 `홈페이지 + 공통 게임 엔진` 구조로 확장해, Lesson 2와 Lesson 3를 한 앱에서 선택해 사용할 수 있게 만든다.

## 핵심 사용자 흐름

1. 사용자는 앱 첫 화면에서 `Lesson 2`, `Lesson 3` 중 하나를 선택한다.
2. 선택한 단원의 게임 화면으로 이동한다.
3. 게임 화면에서는 기존과 동일하게 랜덤 뽑기, 중앙 카드 무대, 효과음, 초기화 기능을 사용한다.
4. `홈으로 돌아가기` 버튼으로 다시 단원 선택 화면으로 이동할 수 있다.

## 화면 구조

### 홈 화면

- 앱 전체 제목
- 간단한 사용 안내
- `Lesson 2`, `Lesson 3` 선택 카드 2개
- 각 카드에는 단원명, 카드 수, 짧은 설명, 시작 버튼을 표시

### 공통 게임 화면

- 현재 단원명과 설명
- `홈으로 돌아가기` 버튼
- 카드판
- 중앙 카드 무대
- 랜덤 뽑기 / 초기화 버튼
- 보조 상태 정보

## 레슨별 차이

### Lesson 2

- 이미지 5장
- 3x2 카드판에서 `그림 카드 5장 + 상태 카드 1장`

### Lesson 3

- 이미지 6장
- 3x2 카드판 전체를 `그림 카드 6장`으로 사용
- 상태 정보는 카드판 바깥의 별도 상태 영역에서 공통으로 제공

## 기술 설계

- 정적 웹앱 유지
- 단원별 정보는 별도 데이터 모듈로 분리
- 게임 로직은 기존 `game-state.js`를 재사용
- 홈 화면과 게임 화면 전환은 단일 페이지 상태 전환으로 구현
- 필요 시 `location.hash`를 사용해 직접 진입도 가능하게 유지

## 모듈 책임 분리

- `lesson-data.js`: 단원별 메타데이터와 카드 자산 정의
- `screen-state.js`: 홈/단원 화면 전환과 해시 해석
- `lesson-view.js`: 단원별 보드 슬롯, 상태 표시, 버튼 라벨 계산
- `app.js`: DOM 이벤트 연결과 렌더링 오케스트레이션

## 테스트 전략

- Lesson 데이터 구조 검증
- 해시 기반 화면 상태 해석 검증
- Lesson 2와 Lesson 3의 보드 슬롯 차이 검증
- 기존 게임 상태 테스트 유지
